# Lint rules

Generated by `python3 spec/tools/portrayal/lint.py --list-rules --markdown`;
a test fails when this page and the linter disagree. A finding prints as
`path: [Lnn] message`: the message is about the file, this page is about the rule.

A warning passes the lint and an error fails it. *At verified* means a device
that claims `maturity: verified` gets an error where one still being drawn
gets a warning.

| code | scope | the rule | why | what to do | severity |
|---|---|---|---|---|---|
| L0 | any yaml | the file parses as YAML | A file that does not parse cannot be drawn, exported or checked at all, so the fault is reported at its own line rather than as an unexplained failure further on. | fix the syntax the message points at; a `#` after a space inside an unquoted string starts a comment | error |
| L1 | any yaml | the file validates against its schema | The renderer, the exports and every later check read the shape the schema describes, so a misspelt key or a value of the wrong type would otherwise be ignored or misread without a word. | the path in the message names the key; the schema's description for it says what is accepted | error |
| L2 | any id | every id and segment matches ^[a-z0-9]+(-[a-z0-9]+)*$ with no double hyphen | Every id becomes a segment of the element ids and data paths in each drawing, so a capital, a space or a double hyphen would break the addresses that selectors, the explorer tree and the exports rely on. | rename the id; it becomes a DOM id segment in every SVG | error |
| L3 | component | every contracted element id exists in every declared skin | A skin without an element the contract promises draws that variant without the node the explorer, the lamp states and the 3D relief address, so the element silently vanishes when that skin is chosen. | add the element to the skin, or remove it from `elements:` | error |
| L4 | component | each skin's viewBox matches the contract size | A skin drawn to a different size from its contract is stretched or shifted when it is placed in millimetres, so every opening and lamp in it lands in the wrong place on the faceplate. | set `viewBox="0 0 <w> <h>"` and mm width/height from `size` | error |
| L5 | device | placement refs resolve in the library, and instance ids are unique per view; no placement ref, and no bay's `accepts` or `default`, is a `kind: kit`, which a device names only from `chassis.kits` | A placement that resolves to nothing, or two parts sharing one id in a view, leave a missing part or an ambiguous address in the drawing, and a rail kit placed like a module draws something no build contains. | fix the `ref` (namespace/name@major) or the duplicate id; list a rail kit under `chassis.kits` and place its parts, if anything, by their own refs | error |
| L6 | device | a bay's default appears in its accepts list | A bay whose default it does not accept draws a module the vendor says does not fit there, and a bay nothing ever fills draws as an empty frame in every drawing of the device. | add the default to `accepts`, or change the default | error or warning |
| L7 | device | region members reference existing instance ids | A region framing an id that is not in its view frames nothing, so a reader sees a labelled block whose members the drawing cannot find. | name ids that exist in the same view | error |
| L8 | device | a configuration seats only what its bays accept, and only in bays that exist in it | A configuration that seats a module its bay does not accept, or fills a bay its build does not have, shows a fit-out nobody can order, or silently drops the module. | add the occupant to the bay's `accepts`, or seat something the bay takes; for a bay `only-in` scopes out, add the configuration to it or drop the key | error |
| L9 | component | a conforms-declared size matches spec/schemas/standards.yaml | A part that claims a published standard but is drawn to another size passes a wrong aperture to every device that places it, with the standard's name vouching for it. | take the size from the registry, or drop `conforms` if the part is not the standard aperture | error |
| L10 | component | composed parts resolve, ids are unique, composition does not cycle (depth <= 4), and neither a part nor a bay's `default` or `accepts` is a `kind: kit` | A composition that names a missing part, repeats an id or loops back on itself cannot be drawn, and a kit composed as a part offers something no configuration can hold. | fix the `parts:` refs; a part must not compose itself; a kit is named from a device's `chassis.kits`, never composed or seated | error |
| L11 | component | interface/mates declarations carry a `mate` connection point, and a wrapper keeps the interface of what it composes | A receptacle or plug with no mate point has nothing to align to, so it cannot be seated, and a wrapper that changes its interface lets parts pass the fit check against something they do not really mate. | add `connection-points.mate`; do not change the interface in a wrapper | error |
| L12 | device | mate-to resolves to a receptacle whose interface the occupant mates; a seated part's `rate` is at or below its cage's media | A drawing could otherwise seat a part where it cannot go, such as a QSFP transceiver in an SFP cage or a 10G cable in a 1G cage, while still looking right. | point `mate-to` at the receptacle id; check `interface` and `mates` agree; seat a part the cage offers | error |
| L13 | device | two placed components do not occupy the same faceplate area | Two parts on one patch of faceplate are almost always a sizing mistake, hidden in the flat drawing where one paints over the other and plain in 3D as a lamp hanging over a port. | move one, or declare `for:`/`under:` when one deliberately sits on the other | error |
| L14 | device | a silkscreen `for:` target exists and is nearby | A legend or lamp bound to a part that does not exist, or to one across the panel, tells a reader and every tool that follows the binding something false about what it annotates. | name the placement or bay the mark annotates, and anchor the mark at it | error |
| L15 | device | a device at `modelled` or above has a provenance block good enough for the level | A device that claims to be modelled or verified could otherwise carry figures with no source, so nobody could tell a measured dimension from a guess. | add provenance for every figure, or lower `maturity` | error |
| L16 | device | keys inside a view read in manufacturing order | Anyone building a device follows the file stage by stage, so a view written out of manufacturing order teaches the wrong procedure and is harder to compare with its neighbours. | reorder: empty, size, open-frame, panel, silkscreen, components, regions | error |
| L17 | component, device | a placement's or part's group is declared under `groups:`, and a component that declares groups puts every port part in one | A group used but never declared carries no vendor term, role or numbering origin, and on a card, ports half inside and half outside groups read as two kinds of port where there is one. | declare the group with term, role and index-origin; join the loose port to a group | error or warning |
| L18 | device | a port whose component names only a family of media (an `sfp` cage, which SFP, SFP+ and SFP28 share) states its own media, on the placement or on its group | A port that takes its media from a cage covering a whole family shows only the family, so an SFP28 port reads as SFP and the model looks complete when it is not. | declare the media the datasheet gives under the placement's or the group's `attrs.media` | warning |
| L19 | device | an indicator declares `for:` the thing it indicates - a lamp, button or display placement, and a bay in a group whose role is `indicator` | A lamp, button or display with no stated subject leaves its meaning to a naming convention a reader can guess and no tool can read. | add `for:` to the lamp placement or the bay; a panel that reports on the whole box is `for: chassis` | warning |
| L20 | component, device | state names are tokens and each `behavior` is well-formed, on a contract's states, an element's, or a placement's | A state written as prose cannot become the class and the chip the viewer builds from it, and a malformed behaviour cannot be animated, so the lamp's real meaning reaches no one. | a state name is a token like `link`; prose goes in `description`; `behavior` is solid, blinking, alternating or sequence, with `behavior.color` for the second colour | error or warning |
| L21 | device | chassis silkscreen does not sit under a bay where the module covers it | A legend printed where a module sits is painted over by it and cannot be read in the drawing. | move the mark, or put it in the module's own skin if the module carries it | warning |
| L22 | component, device | a group's declared media/speed matches the ports it holds | A group's attributes are copied onto every member, so a group whose media or speed contradicts a member would quietly relabel that port, for example an RJ45 jack drawn as SFP28. | fix the group's `attrs`, or move the odd port to its own group | error or warning |
| L23 | component, device | a port group is one family, or says in `mixed:` why it is not | A group mixing connector families cannot carry shared attributes, and an unexplained mix cannot be told from ports nobody has sorted yet. | split the group by family, or add `mixed:` naming the job they share | warning |
| L24 | device | `attrs.other` is counted so the long tail cannot go quiet | Keys left in the catch-all section are counted on every run, so the catch-all cannot quietly become the place anything awkward is put. | file each key under its section where one fits; otherwise leave it and accept the count | warning |
| L25 | device | one attr key is claimed by one section | Attribute sections flatten into one set of data attributes on the drawing, so two sections claiming one key would let one fact silently overwrite the other. | rename one of the two; keys flatten to data-<key> | error |
| L26 | component | every `class: cutout` element is backed by a conforming contract or a part that resolves to one | An opening with no standard part behind it has a size nothing checks, and the count keeps every such opening visible until a standard or a drawing is found for it. | add `conforms`, or compose the std/ part that owns the aperture | warning |
| L27 | component | a power-bearing module states its power figure or records that no document holds it | A power-bearing module with neither a figure nor a recorded absence leaves power totals short, with no record of which figures are missing. | add `power-output-w` or `power-draw-max-w` from the guide's appendix, or leave the warning as the record | warning |
| L28 | component | a power figure says which way it points and its min/typical/max are ordered | A bare watts figure cannot say whether a part supplies or draws power, and a minimum above its maximum is a transcription slip, so either would corrupt any power budget built from the library. | use `power-output-w` for supplies and `power-draw-*-w` for consumers; never `watts` | error |
| L29 | device | a chassis says how many of the modules it accepts have no figure | A chassis whose modules lack figures would total to a small, confident, wrong power draw, so the count of modules with no figure travels with the total and marks it as a floor. | walk the list; each is either in a document you missed or stays as the record | warning |
| L30 | device | a card whose figure covers its paired module does not sit beside a module that also states its own | When a card's figure already includes its paired module and that module states its own, a sum over the bays counts the pair twice and gives a plausible over-count. | decide which figure carries the pair and say so | warning |
| L31 | device | a distance a side or top view's region label states along the depth ("5.73 in from the front") lands on something drawn there | A region label that disagrees with what the drawing puts there tells a reader a part is somewhere it is not. | correct the distance in the label, or the depth of what it points at | warning |
| L32 | any yaml | no mapping declares the same key twice | YAML keeps the last of two identical keys without a word, so whatever the first one said is lost before any rule or reader sees the file. | remove the duplicate; YAML keeps the last silently | error |
| L33 | device | a bay reserves room for every module it accepts | A module larger than the bay that accepts it is either a part that cannot fit or a figure measuring something else, and either misleads someone planning a fit-out. | size the bay to the largest `insert`/`size` it accepts, or remove the module from `accepts` | warning |
| L34 | device | front and rear occupants sharing a slot column, in every configuration, fit around the midplane | Front and rear modules in one slot column can each look plausible yet together be deeper than the chassis, giving the 3D view and anyone planning a fit-out depths that cannot both be true. | check the two depths against chassis depth; one of them is wrong, or the two cannot be seated together | warning |
| L35 | component | a relief magnitude says where it came from | A relief depth with no stated source looks exactly like a measured one, so neither a reader of the 3D model nor the next contributor can tell a guess from a fact. | add `confidence` and `source` to each `relief.features` entry | warning |
| L36 | component | a `borrowed` relief magnitude names an origin that actually measured it | A borrowed depth claims another part measured it, so a borrowed guess, or a chain of them, would otherwise pass for a measurement in the 3D model. | name a part whose own figure is `measured` or `photo-measured`, or use `estimated` | error |
| L37 | component, device | a group says what it is for and has members | Without a role nothing reading the drawing can tell the bays the box exists for from the ones that keep it running, and a group with no members promises parts that are not there. | add `role`; delete a group nothing joins | warning, error at verified |
| L38 | component | printed text in a skin sits in `<g id="silkscreen">` unless the part is applied over the panel | Printing grouped as silkscreen is a layer of its own, so a drawing without the printing drops every legend and keeps the metal without relying on a sweep for loose text, and anything reading the skin can tell what is printed from what is cut. | wrap the text nodes in the silkscreen group | error |
| L39 | device | the panel's holes agree with what goes in them: no overlap, standard sizes, no legend on a hole, every port has one where cutouts are declared | A hole that disagrees with its part draws metal the hardware does not have, misleading anyone checking the drawing against the real panel. | fix the cutout size/position, or the placement; one wrong `ref` shows as many overlaps | error or warning |
| L40 | device | a pluggable cage says which optics run in it, and optics prose names a group that exists | A cage's shape says which optics fit, not which ones work, so someone fitting an optic to a port would have nothing to go on. | add the group's optics attrs, or fix the group name in the prose | warning |
| L41 | device | a bay or placement scoped to configurations names ones that exist, not all, not none | A typo in `only-in` drops a bay or part from the configuration it was meant for, and scoping to every configuration leaves the part out of one added later. | fix `only-in` | warning |
| L42 | device | a silkscreen mark says what it annotates, or `chassis` for printing about the whole unit | A legend with no owner cannot be checked for sitting beside its part or hidden by the module that covers it, and nothing reading the drawing can say what is printed next to a given port. | add `for:` | warning, error at verified |
| L43 | device | a front or rear view as wide as the rack face still has its ears in it, unless the device is a `rack-face` part, which is its ears, states `chassis.ears: behind` (or `ears: {behind: true}`), whose face is the part, or has a body as wide as the rack (a blanking plate, whose ears are built into the face) | The library draws the metal between the ear folds, and the ears are added from the chassis, so a face measured across the ears puts every port off by an ear's width and gives the rack a body wider than the opening it fits. | model the body between the ear folds; record the ear extent in provenance | warning |
| L44 | device | panel decor agrees with the face: a patterned field is not buried under parts, printing does not run off the edge, no decor lies wholly off the face | Decor that is buried under parts, runs off the face, or lies wholly off it shows vents or printing the real panel does not have, and usually means something was mismeasured. | move or trim the decor | warning |
| L45 | device | a face of a device at `modelled` or above draws something, unless a gap's `scope` names the face | A face that only declares a size is not drawn, so the device would claim more than it shows unless the author records why the face stays empty. | draw the face's content, estimated and marked where it must be, or open a gap whose `scope` names it; an `empty:` sentence records where you looked and does not clear this | warning |
| L46 | component | composed parts do not collide inside the part | Two parts composed into the same place render as doubled or buried detail, such as one cage stacked over another, which a reader would take for real hardware. | move a part, or say in provenance that the layering is deliberate | warning |
| L47 | component | a state nothing draws is not declared | The viewer would offer a lamp state, such as fault, that changes nothing when chosen, because no drawn lamp takes the state's colour. | draw a lamp element for the state, or remove the state | warning |
| L48 | component | a bay the contract declares is drawn by a skin | With no drawn element for the bay a seated module has nothing to nest under, so the explorer hangs it off the chassis rather than inside the part that holds it. | draw the bay opening in every skin, or remove the bay | warning |
| L49 | device | members of one group, cut to one size, sit on one pitch | Uneven spacing among same-size members of one group is nearly always a misreading, and drawn as found it puts modules where the hardware does not. | re-measure; an uneven pitch is usually a mis-read, not a finding | warning |
| L50 | component | printing inside a skin lands at least half on the part, and nothing drawn after it covers half of it or more | Printing that runs off the edge of the part, or is covered by something drawn after it, is printing the reader cannot see while the drawing claims it is there. | move or shorten the text so it stays on the part, or move what is drawn over it | warning |
| L51 | component | a class has a power role in spec/schemas/power-roles.yaml | A class with no power role is never asked for a figure, so a power total quietly counts an unknown part as zero and presents a lower bound as the total. | add the class under `draw`, `supply` or `passive` in power-roles.yaml | warning |
| L52 | component | a stated power figure says where it was read from | Vendor power figures vary with conditions, so a number with no source cannot be rechecked or tied to the row it came from. | add the provenance key the message names | warning |
| L53 | device | content changed without the version bump the change requires (see devicelock) | Without it, a drawing someone has cached or imported goes stale without notice: a moved slot breaks a saved coordinate just as a renamed id breaks a saved reference. | bump `version`: patch for wording, minor for additions, major for geometry or ids | warning, error at verified |
| L54 | device | a gap's scope names a group, view, configuration, id or attribute the device has | A gap scoped to something renamed or never declared would be read as applying to a part of the device that does not exist. | fix the `scope`, or drop it | warning |
| L55 | library | every vendor namespace is in spec/schemas/vendors.yaml | A namespace missing from the registry breaks the link from the name on the metal to the company that owns it now, so a search under the current name finds nothing. | add the vendor to the registry with display, role and source | error or warning |
| L56 | listing | a listing sits under a software vendor in spec/schemas/vendors.yaml and lists a device that exists - every configuration it overrides, port it names and component it maps is the hardware's | A listing that names a port, configuration or part the hardware lacks would export interfaces and modules to a DCIM that no box has. | register the NOS vendor with role software, point `hardware` at a device's <namespace>/<directory>, and name only configurations and ids that device declares | error |
| L57 | device | exactly one configuration is `kind: base`, and each says whether it is orderable | Without a kind on each configuration the DCIM export can name a device type after an illustration rather than an orderable chassis, and the drawing can open on something nobody can buy. | set `kind` on every configuration | error, or warning that is an error at verified |
| L58 | component | a cage's own connection point agrees with the aperture inside it | When the two points disagree, a cable drawn to the declared point and a module seated on the aperture's point end up in different places. | move the connection point to the composed aperture's | warning |
| L59 | device | SKUs live on configurations, not at the top level | The DCIM export reads part numbers per configuration, so it never sees SKUs left at the top level: one already on a configuration is a second copy that can go stale, and one on none is an orderable build missing from the export. | move `part-numbers` into the configuration they belong to | warning |
| L60 | device | a face that declares itself empty is actually bare | A face declared empty counts as finished without drawing anything, so a stale claim would contradict the drawing and pass the face on false grounds. | remove the `empty:` or the content; not both | warning |
| L61 | device | a legend is centred on the thing it names, or plainly not trying to be | A legend a fraction of a millimetre off the part it labels looks wrong to anyone who zooms in. | centre it, or move it clear | warning |
| L62 | device | an id names the connector the way the rest of the library does | An id that names the connector rather than its job becomes false when the part changes, and two correct models of one device end up with different names for the same port, so references and exported interface names drift. | use the convention the message quotes (e.g. `port-N`, `led-port-N`) | warning |
| L63 | device | a configuration binds each face to a view that draws that face; a hole is derived from its part, not drawn around it | A face bound to a missing view, or to another face's view, makes an impossible front and rear pairing look declared, and a hole drawn around its part is a second record of the opening that can disagree with the first. | fix the `views` binding, or derive the cutout from the placement | error or warning |
| L64 | device | nothing is bolted to, or printed on, an air hole | A vent field is open air, so a legend placed on it is printed on nothing and a jack is mounted to nothing. | move the part or the mark off the vent field | warning |
| L65 | component | a DC power part with nothing seated states what it can pass | On a DC chassis a power entry module is the only way power gets in, so if it states no rating nothing says how much power the chassis can take. | add `power-output-w` for the PEM/terminal | warning |
| L66 | device | a power group with more than one bay states its redundancy | Two supplies mean either double the capacity or one plus a spare, so someone adding up the bays could provision for twice what the box can rely on. | add `attrs.redundancy` (e.g. `1+1`) and a `redundancy-note` citing the guide | warning |
| L67 | device | a control-plane or fabric group with more than one bay states its redundancy | Someone counting control or fabric cards would take a standby spare for working capacity and overstate the headroom. | as L66, for the RE/RP/fabric group | warning |
| L68 | library | a measurement keeps one attr name and one section across the library | A comparison that cannot find one spelling shows a blank or a wrong figure with nothing to warn the reader, and a key filed under different sections cannot be found by section. | use the name the message quotes | error or warning |
| L69 | device | a cooling group with more than one bay says how many fans it can lose | Without a stated figure nobody comparing devices or planning cooling can tell how many fans the box can lose and keep running. | add `attrs.redundancy` (e.g. `n+1`) and a note | warning |
| L70 | device | a `fact:` gap names a real fact and does not contradict the device | A gap scoped to a misspelt fact leaves the comparison showing a bare blank although the search was done, and a device that states a figure while calling the vendor silent on it shows a number and a retraction at once. | fix the gap's scope or remove it | error |
| L71 | component | a body box reaches no further than the part says it is deep; a round one states its axis (a ring its wall) and is square across it; one that `shows` a drawing is a box of a part declaring that face | A body box deeper than the part gives the wrong bay hole, pull distance and fit checks, and a round piece with no axis or a non-square section builds as an oval in 3D. | shrink the body box or raise `body.depth`; state `axis`/`wall` or square the envelope; declare the face or drop `shows` | error or warning |
| L72 | device | a bay's `plan:` or `rear:` lands in a view that exists, inside the chassis | A bay projected into a view or neighbour that does not exist draws nothing and raises nothing, so the plan or rear view silently loses the part. | fix the plan view name or the coordinates | error or warning |
| L73 | component | a field prints somewhere, and what prints is a field; a node a field paints states no relief `color`, so its 3D sides follow the field | A form would offer a field that changes nothing on the drawing, or the drawing would paint from a value no form can set, and a fixed relief colour leaves a field-painted part's 3D sides the wrong colour. | add a `data-from` text node for each field, or remove the field; drop a relief feature's `color` on a field-painted node | error or warning |
| L74 | component | a lamp that declares states is painted from the lamp-colour variable | A lamp painted in a literal colour ignores every state its contract declares, so in 2D and 3D it can never light the way the viewer says it does. | fill or stroke the lamp node with `var(--led-color, <off colour>)`, not a literal colour | error |
| L75 | component | a slot's structured facts agree with its prose, and lanes fit the connector | A slot's prose and its structured facts would drift apart, so a reader and the card-fit check would see different slots, and a lane count wider than the connector is a typo, not a slot. | fix `lanes`/`connector` or the description | error |
| L76 | device | the RJ45 census: every Ethernet jack says whether it has lamps | Every Ethernet jack has to answer whether it has link lamps the same way, or a drawing can leave out lamps the hardware has, or add them to a console jack, and the viewer cannot light them consistently. | use std/rj45@2 with the lamp parts, or say in provenance the jack is bare | warning |
| L77 | component | a `sink` sits in a cavity, because that is what it measures from | A sink with no cavity above it has no floor to measure from, so the recess is declared but never built in 3D, and nothing reports it. | use `pocket` for a recess in an otherwise solid face | error |
| L78 | component | an optical endpoint names a composed connector and a position it has; a front order that names a part's positions names each once, together; a trunk entry names a connector on this face and a position it has | An optical endpoint, front order or trunk entry that names a missing part or position describes a fibre that does not exist, so ports are left unnumbered or numbered twice. | fix the part id or the position number; list every position of the part, or name it bare | error |
| L79 | component | no fibre position is claimed twice, and a split's ratios sum to 100; a source starts one path, unless every path it starts but one carries a `band` (an add/drop filter); several sources reach one destination only as a declared `combine` | Two paths into one bore describe something no ferrule allows, and ratios that do not add to 100 describe a split that cannot exist. | remove the duplicate path, or fix the ratios; write a split as one path with a ratio list, and sources that join as one path with a `combine` list | error |
| L80 | component | every fibre position is reached by a path or declared unused with a reason | A fibre position nothing reaches cannot otherwise be told from a deliberate dead end, so a missed path would pass as a design choice. | route it, or add an `optical.unused` entry saying why it terminates nothing | error |
| L81 | component | a composed pitch respects the standard the part conforms to - equal for a target, no narrower for a floor | Connectors set closer than their standard allows, or off its fixed pitch, draw a port array a mating plug or neighbouring module would not line up with. | move a target onto the standard's pitch, widen a floor to at least it, or say in provenance why this part differs. Where the placements share an x, make their `rotate` agree so a rotated column can be told from a stacked pair | error |
| L82 | component | a part names its plan drawing one way or the other, never both | Two copies of one plan reference agree only until someone edits one and misses the other, and then every reader has to guess which copy counts. | keep `plan:` or `faces.plan`, not both - they mean the same thing | error |
| L83 | component | a declared face names a real component, is not the part itself, and that component has no face of the same direction | A face ref with a typo draws nothing while the contract still lints, and a face that names its own part, or a direction the named part already has, means the wrong part is drawn. | fix the ref, or drop the face it names if the chain has no meaning | error |
| L84 | component | a face-qualified optical endpoint names a face the part declares | An endpoint qualified with a face the part does not declare resolves to nothing, and its fibre drops out of the map. | add the face to `faces:`, or fix the prefix on the endpoint | error |
| L85 | component | only a face that is another side of the module draws fibres of its own | A connector drawn on a face that is only another view of the same module is not counted, so it is either the front's port drawn twice or a real port missing from the fibre map, and nothing says which. | move the connector onto the face that really carries it, or extend `faces.OPTICAL_FACES` if this direction genuinely is another side | error |
| L86 | component | a module composing a connector the enum spells two ways states its polish | Without a stated polish a module of LC or similar adapters has no port type a DCIM import can take, because the type is spelled UPC or APC. | add `optical.polish: upc` or `apc`, and say in provenance where it came from | error |
| L87 | component | a module naming what its rear IS has a rear face to name | A rear kind on a module with no rear face describes a drawing that does not exist, so the export writes nothing for that side and nothing says so. | add `faces.rear`, or drop `optical.rear-kind` | error |
| L88 | component | a fibre face with more than one row of connectors states its own front numbering | On a face with more than one row of connectors, numbering by position alone guesses the vendor's printed order, so DCIM front ports could be numbered differently from the silkscreen. | add `optical.front-order` listing the fibre part ids in the vendor's printed order | error |
| L89 | library | every component major is reachable from a device, or says why it is not | A part nothing seats would look in the catalogue exactly like one in use, so a reader could choose a part no drawing has ever shown in place. | seat it in a device or in a seated part's bay, or add `unplaced:` saying what would seat it and what is missing | error |
| L90 | device | a manifest's top-level keys read in the canonical order | Keys in one order across every manifest let a reviewer compare two devices line by line, and a contributor copying a neighbour copies the canonical layout rather than an accident. | reorder them; the message prints the order, and docs/device-template.yaml is written in it | error |
| L91 | device | airflow is stated once - on the chassis, and on a configuration only where it differs | Airflow stated in two places drifts, so a change to the chassis could be masked by stale copies, and a reader cannot tell a real difference between builds from repetition. | move it to `chassis.airflow`, or drop the configuration's copy | error |
